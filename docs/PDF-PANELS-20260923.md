# PDF 面板与空白问题复核（2026-09-23）

用户反馈：触控板滚动已改善，但快速滚动出现空白，点击左右面板展开/收起仍卡顿。本轮不测试分隔线拖动的性能，不将合成滚轮读数当作触控板验收。

## 检查发现

- `a6b2659` 在面板动画期间跳过 PDFView 的 `layout`/`draw`。调用计数降低不能证明页面瓦片已完成渲染；冻结也没有消除 SwiftUI 外层宽度动画的表面更新。卸载文档还会留下冻结标记，因此移除此绘制抑制路径。
- 面板动画完成时调用的是届时活动标签的 bridge；中途切标签会把结束通知发给另一份文档。现在保留开始时的实际回调，归还给对应阅读器。
- 原恢复任务提前清空锚点。快速连续切换时，新任务可能把临时 `autoScales=false` 记为原值；旧任务还可能回写新文档。现在按操作种类管理重叠调整，保留原缩放状态至真正恢复，并校验任务代次及文档身份。
- 面板计时诊断原先只把动作阶段纳入大停顿汇总，漏掉落定阶段；动态日志还将已格式化文本当作 NSLog 格式串。两处已修正。计时器迟到量不是屏幕实际掉帧率。

## 修改

PDF 的侧栏、AI 面板和沉浸切换使用禁用动画的事务，一次完成几何布局并恢复阅读锚点。EPUB 保留既有动画。PDFView 正常执行绘制和布局，不使用冻结或私有滚动方法替换。

滚动中每 150 ms 只更新独立的原生页码标签，不再发布 `PDFViewportState.snapshot` 或调用工作区的 `onPositionChange`。实时数字不使用 SwiftUI `numericText` 动画。停稳后统一更新侧栏、AI 上下文、完整几何和保存进度。无需新增页面位图缓存或降低插值质量。

清除面板 A/B 中已弃用的生产分支，保留 `--panel-frame-report` 作为实际生产点击路径的计时工具。

## 用户复测与最终结论

用户在构建 `20260923-094057-25822` 确认“面板好了，快速滚动仍有空白”，因此不能把移除冻结视作滚动空白的完整修复。

该次真实日志仍有约 850–915 ms 的计时迟到，与滚动中页码回调及 AI/侧栏刷新同时出现。复核发现，所谓“轻发布”仅少算了 `pageRects`，仍发布整个视口快照并调用工作区页码回调；后者同时更新多个 SwiftUI 观察对象。因而上一轮“CPU 花在 PDFKit 固有光栅化”的判断并未排除应用侧状态更新。

在构建 `20260923-094614-26077` 隔离实时页码后，用户明确回复“不再出现空白”。该次实际滚动的 +18.5/+20.5 秒计时窗口最大迟到分别为 21.49/12.17 ms，启动段仍有 288.98 ms 尖峰，不能将其描述为整个会话零延迟。用户确认两项问题在本机该 PDF 上解决；这不等于所有文件与所有系统都已覆盖。

最终 7 项回归测试通过，新增断言验证实时页号可以更新而不触发视口观察者或工作区回调，工作区只在停稳后收到最终页号。真实日志另存为 `real-scroll-before-label-isolation.log` 与 `real-scroll-after-label-isolation.log`。

## 维护复盘（用户后续确认当前已解决）

这轮不是单一“PDF 绘制慢”：自动 Vision 文档分析曾带来后台负载；真实触控板卡顿与滚动期向整个工作区发布页码/视口状态有关；快速滚动空白还与跳过 PDFView 绘制的冻结方案有关；面板显隐持续改变 PDF 面宽，触发重复布局与合成表面更新。原生 PDF 窗口和最小 SwiftUI 承载均流畅，说明不能仅凭 `wait_for_synchronize` 栈就断言 PDFKit 或 SwiftUI 本身有缺陷。滚动条拖动流畅也不能替代触控板手势验证。用户现在确认问题已解决，但本轮没有新的全文件、全机器性能测量，不把它写成普遍性能保证。

避免复发时，滚动中的即时反馈只更新独立原生页码标签；完整视口、侧栏/AI 上下文与阅读进度待停稳后发布。不要用冻结 `layout`/`draw`、降低画质或自管滚轮事件掩盖问题。面板显隐保持一次布局并恢复原缩放与阅读锚点，异步恢复必须校验文档身份。诊断前核对唯一运行的进程、实际构建标识和 `dist/Lumen.app` 路径；曾同时存在旧 `dist/.trash` 进程，因此混用构建会使对照无效，但不能据此断定它造成了卡顿。

`--jank-report` 合成事件未进入真实触控板响应式/惯性路径，曾产生计数全 0 的假通过；`--jank-watch` 的计时迟到、CPU 和回调计数可辅助定位，不能单独证明实际画面流畅。以用户真实触控板前后对照验收连续滚动、惯性、快速滚动空白、缩放和面板切换；具体门槛见 [验证文档](VERIFY.md) 与仓库根目录 [维护约束](../AGENTS.md)。
