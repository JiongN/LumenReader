主题与原色的滚动 CPU 开销接近。RSS 包含启动、滚动、截图的整个进程峰值，不能当作稳态内存或断言固定降幅。双面板改变阅读宽度和倍率，不能与全宽模式直接计算性能退化百分比。原色单次最大延迟较高也说明冷启动/调度噪声，不能挑它宣称主题更快。

这是一轮可重复的自动事件对照，主线程计时不是显示帧率，驱动强度低于此前真实触控板采样；不据此宣称已绝对无卡顿。最终触控板手感仍应由用户在新版主题模式下确认。资源释放检查通过，但有限回归不能保证所有文档、长时间运行均无崩溃。

## 追加（本轮修复 b54d52d）：标题摘要区 + 元数据墙标剔除

针对用户「标题摘要处与作者信息、关键词混在一起；跨页段落处理不好」的反馈（Selwyn 2025 实测）：

**根因**：双栏布局 PDFKit 不分栏 → 左右栏行按 y 交错；摘要窄栏被相邻右栏元数据行打断、
窄栏行距大触发 `gapTooLarge` → 20 行摘要碎段；期刊首页元数据（ARTICLE HISTORY /
KEYWORDS / CONTACT / 引用块 / ISSN / 边栏链接 / 版权）混进正文段落流。

**结果（真机 Selwyn）**：
- 第 1 页（封面）18 行 → **2 段**（标题 + 作者），引用块 / ISSN / 边栏 / 版权全剔
- 第 2 页 57 行 → **8 段**：卷号 / 标题 / 作者+单位 / **摘要 19 行完整合并成一段** /
  Introduction / 正文 / 单位 / 版权
- 跨页段：8 条正确合并（`P4[y51] P5[y568]` 等「上页底部→下页顶部」）

**自检**：`--paragraph-report` **54/54**；Swift 单元测试 **43/43**。

⚠️ 已知：`abstract` 不能当墙标（窄栏正文夹具以 "abstract line…" 开头会被误删）；
墙标匹配需**区分大小写**（期刊墙标大写/标题式 vs 正文同词小写）。
⚠️ `--sidebar-tab-report` 在系统负载下**偶发误报 22/23**（`sidebarPane_outline` 幽灵探针，
HEAD 即存在，非本轮引入；trace 加 NSLog 会「虚假通过」。见工作区记忆——未根治，不影响功能）。
