# LumenReader 全面审计与修改记录

## 范围与结论

本次审计覆盖 SwiftUI 窗口与标签状态、PDFKit / WebKit 阅读链路、EPUB 解包与内链、AI 会话和翻译、持久化、更新与发布脚本、主要 UI 入口及工程目录。当前版本已修复会导致 EPUB 翻译失效、解包越界、持久化静默丢数据和发布误报成功的高优先级问题。测试、Debug / Release 构建、签名校验与 EPUB 逐段翻译端到端检查均通过。

审计不等于穷尽所有第三方 PDF / EPUB 变体、所有 macOS 小版本和真实网络服务。下文会明确区分已修复项与剩余风险。

## 架构与 UI 评估

分层总体合理：`LumenKit` 承载可测试的核心能力，`LumenApp` 承载平台 UI 和控制器，每个文档由 `ReaderSession` / `ReaderBridge` 统一 PDF 与 EPUB 能力。最大的长期耦合点位于较大的 SwiftUI 视图、应用内诊断程序与主目标同编译，以及全局 AI 会话和窗口级文档状态之间的边界。它们目前不构成已知崩溃点，但会增加后续改动的回归风险。

UI 的主导航与 macOS 桌面交互一致。本轮把 EPUB 翻译收敛到和 PDF 相同的左侧工具栏，避免功能重复和概念冲突。新应用图标以 `branding/lumen-icon-source.png` 为唯一源稿，`branding/render.js` 生成标准 iconset 和 `Resources/AppIcon.icns`，构建时再复制到 app bundle。

## 剩余风险与建议改法

1. **大型 PDF 批注保存卡顿（P1）**：PDFKit 对原文件的整体写回仍可能占用主线程。建议增加带文档世代号的后台快照写入，写入前保留同目录临时副本，并用 500 MB 以上的含批注文件做负载测试。
2. **后台标签内存（P1）**：切换标签时阅读视图保活，多个大 PDF / EPUB 可累积 PDFKit tile 和 WebKit 进程内存。建议记录最后活跃时间，在内存压力或超过标签阈值时卸载最久未用的阅读视图，保留可恢复位置。
3. **EPUB 书内脚本（P1）**：WKWebView 仍允许 EPUB 正文脚本执行。现有导航规则阻止未经用户点击的外部页面替换，但不能消除恶意书籍的所有行为。建议默认移除 `script`、内联事件和可执行 URL，只向明确白名单文档开放交互。
4. **EPUB 格式覆盖（P2）**：为安全和可预测性，当前拒绝 ZIP64、分卷、加密、链接和解包总量超过 512 MB 的书。这是有意限制。若需扩大覆盖，应优先接入受维护的 ZIP 库并保留当前额度，不要放宽外部命令路径。
5. **会话共享语义（P2）**：AI 会话是进程级共享的，可混合多本文档。已有引用来源校验，但用户仍可能对当前上下文产生误判。建议在会话标题附近持续显示当前文档范围，并为新文档提供一键新会话。
6. **Swift 6 并发迁移（P2）**：两个产品目标仍以 Swift 5 语言模式构建。建议分模块开启严格并发警告，先处理存储和翻译任务的 `Sendable` / actor 边界，再切换整个工程。
