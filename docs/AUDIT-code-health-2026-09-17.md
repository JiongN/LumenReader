## P1（应该修）

### P1-1 解码失败会静默清空并覆盖用户数据（同一类，四个点）

模式：`load()` 里 `entries = (try? decode(...)) ?? 默认值` → 解码失败拿到空值 →
下一次 `persist()` 把**空列表原样写回磁盘**，用户数据被覆盖，且无任何提示。
LESSONS #1（「最近打开」清空）修的是**实例**（补了 iso8601 策略 + 回归测试），
但没修**类**——同样的结构还在另外三处：

| 位置 | 失败后果 |
|---|---|
| `RecentDocuments.swift:84` | `recent.json` 被空列表覆盖，最近打开记录全丢 |
| `ReadingStateStore.swift:34` | 阅读进度（页码/滚动位置）归零后被写回 |
| `MemoryStore.swift:162` | AI 持久记忆全部丢失后被写回 |
| `Settings.swift:409`（`providers ?? []`） | 用户配置的全部 AI 服务商条目消失（密钥还在 Keychain，但配置要重录） |

**修复建议**（类级，一处工具函数）：
`decodeOrBackup(data:type:fileURL:) -> T?` —— 解码成功返回值；失败时把原文件
**改名备份**为 `<name>.corrupt-<时间戳>` 并 NSLog 报错，返回 nil；
调用点拿到 nil 时**保持内存值不变、且本次不触发 persist**。
`RecentDocumentsDecodingTests` 里补一条「坏文件 → 备份存在 + 内存不归零」的断言。

### P1-2 `ReadingStateStore.save` 是 300ms 防抖 + 静默写

`try? data.write` 失败无任何上报（P1-1 的修复顺带覆盖上报这一半）。
阅读进度丢一次用户未必发现，但**丢失后没有任何线索可查**。
