# 中文文献图谱数据源可行性（2026-09-28）

## 当前结论

用户确认无法取得知网、万方接口授权，因此本项目已搁置两库的直连接入；下述接口条件仅作为调研记录。当前继续使用本地 PDF 参考文献提取与 OpenAlex 匹配，中文文献覆盖取决于用户持有的 PDF 和 OpenAlex 收录情况，不能形成两库的完整被引网络。

万方具备可确认的**中文题录检索与详情补全**接口，但公开文档尚未给出逐篇参考文献或施引文献的关系接口。知网研学开放平台展示数据 API 与应用审核流程；未找到可公开核验的引文关系接口、响应结构及授权范围。两者目前都不能直接作为本应用的“真实引文边”来源。登录网页或拥有个人数据库订阅，不等于获得桌面软件的数据接口授权。

当前可用路径仍是：用户持有的 PDF 明确列出的参考文献 → 本地提取引用边 → 用 DOI 或可编辑标题核对 OpenAlex 题录 → 在 OpenAlex 收录范围内继续扩展。无法匹配的中文文献保持本地未核对节点。

## 已核实的接口与缺口

| 数据源 | 可确认能力 | 接入前提 | 图谱缺口 |
| --- | --- | --- | --- |
| 万方开放文献检索平台 | `POST /openwanfang/getQuery` 检索、`Get` 详情、向量检索；期刊字段含标题、作者、摘要、DOI 等，部分集合有被引次数检索字段 | 平台应用的 `X-Ca-AppKey` 与 `Authorization: APPCODE`；须确认具体产品授权、配额、缓存和展示许可 | 已公开目录只列 Query/Vector/Get；被引次数不是施引文献 ID 列表，不能据此构图 |
| 知网研学开放平台 | 门户说明提供数据 API；可见的应用流程需申请接口并等待审核 | 平台应用和相应接口授权 | 尚无经核验的公开“参考文献/施引文献列表”接口契约；不能用页面内部请求充当稳定 API |

依据：[万方官方开放平台](https://apps.wanfangdata.com.cn/open)、[万方官方 API 目录](https://github.com/wanfangdata/wfdata-open-skills/blob/master/skills/wfdata-search/references/api-catalog.md)、[万方官方技能的认证说明](https://github.com/wanfangdata/wfdata-open-skills/blob/master/skills/wfdata-search/SKILL.md)、[知网研学开放平台](https://openx.cnki.net/)（本站在本次检索环境中不能直接读取接口目录；可见的大学镜像仅证明应用申请/审核机制，不作为引文接口存在的证据）。

## 可实施的分阶段方案

1. **题录增强：**拿到万方开放平台应用权限后，在设置中分别保存 AppKey 与 APPCODE；用中文标题、作者、年份、DOI 检索并展示候选，由用户确认。使用 `wanfang:<collection>:<id>` 保存身份，保留 OpenAlex ID 与 DOI 的对应关系；题录来源、被引统计来源分别标明，不混用两库的被引量。此阶段只增强节点题录和可搜索范围，不新增“引用”边。
2. **引文边接入：**向万方或知网取得正式文档，确认能按论文 ID 返回参考文献 ID、施引文献 ID、分页/排序、边来源、配额及本地缓存/展示许可。拿到真实样例和授权后，做可注入客户端和契约测试，把提供方 ID 映射到现有 `GraphPaper` / `GraphEdge`，箭头只由返回的关系事实生成；同一 DOI 的跨源节点先核对再合并。
3. **降级与隐私：**源不可用时继续显示本地 PDF 与 OpenAlex 的既有图谱；凭据只发给对应平台，不记录到日志、截图或配置导出。没有关系接口时，搜索/语义候选只能标为推荐或待核对，不能用实线引用边连接。

要启动第二阶段，需要平台提供**对应应用的接口授权与样例**，尤其是参考/施引文献列表的请求、响应、授权展示范围和缓存期限。个人网页账号或机构 IP 登录不足以推导出这些条件。
