一、规则入口精简（已完成）

  • .claude/rules/persistence-coding.md —— 编解码策略必须成对相邻书写 + 防静默清空两条防御规则。
  • .claude/rules/design-ui.md —— Apple 风视觉/动效/图标规则（<300ms、ease-out、降饱和、AIIcon 统一字形）。
  • .claude/rules/branding-assets.md —— 图标唯一源管线（SVG → render.js → icns），禁手绘路径。
  • docs/LESSONS.md —— 错误沉淀账本：现象 → 根因 → 沉淀到哪，已登记 6 条。

三、/code-health 审计结果

总评：整体健康度良好——强制解包几乎为零（as! / try! 均为 0）、无 TODO 欠账、引擎层 0 处 import SwiftUI/AppKit。但存在一条系统性缺陷链：解码失败 → 静默置空 → 自动保存覆盖原文件，RecentDocuments 的 iso8601 事故只是它第一次显形，另有 5 处仍在裸奔。

P1 崩溃风险 / 维护成本（6 条，摘要）

  • AnnotationStore 是唯一没有 @MainActor 的 Store，有并发写坏窗口 → 补隔离。
  • 13 个文件 >500 行（最大 PDFController.swift 1267 行）→ 优先拆 PDFController。
  • wireCallbacks 227 行 / 内联 JS 209 行 / 命令表 133 行 → 各自拆分。
  • LaunchDiagnostics.swift:638 唯一一处运行时强解 contentView! → guard。

P2 卫生（5 条，摘要）

  • commitSidebarWidth / ui.sidebarWidth 是死代码（布局已固定 248pt）→ 删除。
  • Annotation 用默认 Double 时间戳、其余 Store 用 iso8601——两套约定并存是事故温床 → 统一。
  • 除 RecentDocuments 外其余 5 个 Store 零回归测试 → 按现有模板补齐。
