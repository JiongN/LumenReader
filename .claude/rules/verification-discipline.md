# 验证纪律 — 本会话沉淀（2026-09-17 深夜批次）

> 来源：模型 chip 不可见、侧栏 214.4 假警报、QA 破坏实验未还原三件事。
> 这些不是代码 bug，是**验证方法**的坑，适用于本项目所有后续改动。

## 1. 探针报「占位多宽」，像素才能证明「画没画出来」

布局探针（`.layoutProbe` + `--layout-report 1`）给的是 frame，**它对一个 7.5pt 宽的
隐形元素也会老老实实报 7.5**——数字看着"合法"，用户眼里就是「按钮不见了」。
凡是「某控件用户说找不到/显示不对」，验收必须两道都过：

1. 探针数值 + 断言（宽度 ≥ 阈值、位置在预期区间）；
2. `--capture-screen 1` 真实像素 + sips 裁剪放大，**人（或模型读图）确认看得到内容**。

## 2. 「可截断」等于「最小宽度为 0」

`Text.frame(maxWidth:)` + `.truncationMode` 让文本可以压到 0 宽。它和
`.layoutPriority(1)` 的兄弟视图同处一个 HStack 时，会被一路挤到隐形。
**规则：同一有限宽里竞争的 chip/按钮，必须显式给 `.frame(minWidth:)`**，
并把文本上限收窄到「minWidth 减去自身内边距」以内，否则会反过来挤输入框。
实例：`AIPanelView.modelSlotMinWidth`（108）+ `maxTextWidth: 80`。

## 3. 测量前先看工作树干不干净

任何「实测值不符合承诺」，第一步 `git status`，其次才怀疑算法。
脏树上的一切测量都不可信——本会话侧栏量出 214.4pt，差点当成真缺陷去改算式，
实际是 QA 做证伪实验改了 `sidebarWidth` 没还原。

## 4. 破坏实验必须「进得去、出得来」

证伪实验（故意改坏代码确认断言会红）是必要的，但**中断就可能留下脏树**。
规则：实验开始前 `git stash list` 记底、结束（无论成败）必须 `git status --short`
归零并在回报里附上；能用 `#if DEBUG` / 环境变量开关做的破坏实验，就不要真改文件。

## 5. 快捷键问题先读用户的 keybindings.json

默认值表对着看三遍也没用——覆盖项在另一个文件里，且记录器存的是**输入法产出的字符**
（`】` U+3011 物理按不出来）。`--keys-report 1` 会打印「← 已自定义」。

## 6. 解码失败的默认值不能直接覆盖回磁盘

见 `docs/AUDIT-code-health-2026-09-17.md` P1-1：`(try? decode) ?? 默认值` +
下次 persist = 用户数据静默清零。失败必须先备份原文件、内存值保持不变。
